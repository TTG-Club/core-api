# Discord: пинг и публикация новостей подписчикам

Новости уходят в канал через входящий вебхук — см.
[DiscordPublisher](../src/main/java/club/ttg/dnd5/domain/article/service/DiscordPublisher.java) и
[ArticleDiscordPublicationScheduler](../src/main/java/club/ttg/dnd5/domain/article/service/ArticleDiscordPublicationScheduler.java).
Вебхук самодостаточен: весь адрес канала зашит в `DISCORD_WEBHOOK_URL`, отдельный бот для отправки не нужен.

Этот документ — про две вещи поверх отправки: **пинг** участников сервера и **«Поделитесь с
подписчиками!»** (кросспост в announcement-канале).

## Пинг участников канала

В редакторе новости, когда выбран канал Discord, появляется выбор «Пинг в Discord»: **Без пинга** /
**@everyone** / **@server**. Значение хранится в `article.discord_mention`
([DiscordMention](../src/main/java/club/ttg/dnd5/domain/article/model/DiscordMention.java)).

Как это работает:

- Строка пинга (`@everyone` или `<@&id роли>`) идёт **первой строкой первого сообщения** поста, над
  заголовком. Хвостовые сообщения длинной новости не пингуют — звеним ровно один раз.
- Разрешение на звон выдаётся точечно, через `allowed_mentions`: `@everyone` — `parse: ["everyone"]`,
  роль — `parse: []` плюс явный список `roles: ["<id>"]`. Всё остальное (`@everyone`, роли и юзеры,
  случайно попавшие в текст новости) не звенит никогда — это поведение по умолчанию было и раньше.
- **Пинг ставится до публикации.** Если включить его у уже отправленной новости, планировщик
  отредактирует пост и строка пинга появится в тексте, но уведомления не будет: синхронизация правки
  уходит с `allowed_mentions: {parse: []}`. Сделано намеренно — Discord на `PATCH` разбирает
  упоминания заново, и без явного запрета каждая правка новости звенела бы каналу повторно.

Права вебхуку выдавать не нужно — вебхук может упоминать `@everyone` и любые роли, даже
немаршрутизируемые (роль не обязана быть «упоминаемой»).

### Настройка роли server

Вариант «@server» пингует роль, id которой задан в окружении:

```
DISCORD_SERVER_ROLE_ID=123456789012345678
```

Где взять id: в Discord включить «Режим разработчика» (Настройки → Расширенные), затем в настройках
сервера → «Роли» ПКМ по роли → «Копировать ID роли».

Если переменная пустая или в ней не число, вариант «@server» просто не пингует: новость публикуется
без пинга, в лог пишется предупреждение. Сделано намеренно — опечатка в конфиге не должна ронять
публикацию (Discord отвергает весь запрос при кривом id).

## «Поделиться с подписчиками» — руками в Discord

Канал новостей — **announcement-канал** (иконка рупора): другие серверы могут на него подписаться, но
подписчики получают только те сообщения, которые **опубликованы**. Публикуется это в Discord вручную и
автоматизации с нашей стороны не имеет — сознательно.

Где кнопка: навести курсор на пост в канале → в панели справа значок **рупора** («Опубликовать»).
В меню «...» и инлайн-подсказкой «Поделитесь с подписчиками!» её нет: подсказка показывается только
автору сообщения, а автор наших постов — вебхук.

Что важно помнить:

- У **длинной** новости пост уходит несколькими сообщениями — публиковать надо **каждое**, иначе
  подписчики получат только начало.
- **Лимит Discord — 10 публикаций в час на канал** (и для людей, и для ботов).
- **Пинги подписчикам не передаются**: Discord вырезает из копии `@everyone`, `@here` и упоминания
  ролей — звенит только наш сервер.
- Правки и удаление поста доезжают до подписчиков сами: планировщик правит исходное сообщение, а копии
  в подписанных каналах синхронизирует Discord.

Автоматизировать это можно только ботом: в API за публикацию отвечает
`POST /channels/{channel_id}/messages/{message_id}/crosspost`, и он требует авторизации ботом с правом
**Управление сообщениями** в канале (сообщение вебхука для бота чужое). Вариантов два — свой бот
(токен в окружении, core-api дёргает ручку после отправки поста) или готовый внешний автопубликатор
вроде AutoPublisher с top.gg, но тот публикует **всё подряд**, без выбора по новостям. Пока решено
жать руками: кода в проекте под это нет.
